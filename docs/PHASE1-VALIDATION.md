# المرحلة الأولى — خطة التحقق ومعايير القبول

## ما تم تنفيذه في الكود
- طبقة موحدة لتشغيل ADB وscrcpy دون shell.
- اكتشاف الأجهزة وحالات `device` و`unauthorized`.
- الاقتران اللاسلكي، الاتصال بعنوان IP:PORT، وتهيئة TCP/IP.
- تشغيل البث مع اختيار H.264/H.265/تلقائي، سقف FPS، معدل البت، ملء الشاشة، وحد أقصى اختياري للحجم.
- رسائل أخطاء عربية وفحوص تشخيصية.
- اختبارات وحدات آلية وسير CI على Windows وUbuntu.

## ما لا يمكن إثباته من GitHub وحده
لا يمكن من خدمة GitHub وحدها قياس جودة بث حي أو تأخير طرف إلى طرف أو packet loss أو توافق MediaCodec على هاتف المستخدم. هذه اختبارات أجهزة فعلية وتتطلب توصيل الهاتف والكمبيوتر وتشغيل البث وقياسه.

## قائمة اختبار الجهاز الفعلي
- [ ] `mirage doctor` يعثر على ADB وscrcpy ويعرض الإصدارين.
- [ ] USB: الهاتف يظهر بحالة `device` بعد الموافقة على RSA.
- [ ] USB: بث مستمر 10 دقائق بلا انهيار.
- [ ] Wi-Fi: الاقتران اللاسلكي ينجح باستخدام عنوان ومنفذ الاقتران الصحيحين.
- [ ] Wi-Fi: الاتصال ينجح باستخدام عنوان ومنفذ الاتصال الصحيحين.
- [ ] نقطة اتصال الهاتف: بث 10 دقائق مع تسجيل FPS والانقطاعات.
- [ ] نقطة اتصال الكمبيوتر: بث 10 دقائق مع تسجيل FPS والانقطاعات.
- [ ] اختبار H.264 وH.265 إذا كان الهاتف يدعم كليهما.
- [ ] تدوين دقة المصدر، متوسط FPS، أدنى FPS، ومعدل البت.
- [ ] قياس التأخير بكاميرا عالية السرعة أو أداة قياس مناسبة، وعدم تقديره بصرياً فقط.

## حكم الاكتمال
الملفات والاختبارات البرمجية تمثل تسليم المرحلة الأولى من ناحية طبقة التنسيق والاتصال. لا توصف المرحلة بأنها مختبرة ميدانياً أو مكتملة بنسبة 100% قبل إكمال قائمة اختبار الجهاز الفعلي أعلاه. لا توجد نتيجة أداء مضمونة مسبقاً.
