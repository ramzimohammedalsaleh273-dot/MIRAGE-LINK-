# المرحلة الأولى — خطة التحقق ومعايير القبول

## ما تم تنفيذه في الكود
- طبقة موحدة لتشغيل ADB وscrcpy دون shell.
- اكتشاف الأجهزة وحالات `device` و`unauthorized`.
- مساران مستقلان: USB اختياري، وWi-Fi عبر Android Wireless debugging دون كابل.
- اكتشاف خدمات الاقتران والاتصال عبر ADB mDNS، مع استخدام عناوين ومنافذ Android المعلنة ديناميكياً.
- الاقتران الأول برمز Android المؤقت، ثم الاتصال اللاحق دون إدخال IP:PORT يدوياً في الواجهة.
- لا يفرض مسار Wi-Fi منفذاً ثابتاً، ولا يستخدم `adb tcpip` أو USB كخطوة تمهيدية.
- تشغيل البث عبر scrcpy مع اختيار H.264/H.265/تلقائي، سقف FPS، معدل البت، ملء الشاشة، وحد أقصى اختياري للحجم.
- رسائل أخطاء عربية وفحوص تشخيصية.
- اختبارات وحدات آلية وسير CI على Windows وUbuntu، وبناء حزمة Windows المحمولة.

## ما لا يمكن إثباته من GitHub وحده
لا يمكن من خدمة GitHub وحدها قياس جودة بث حي أو تأخير طرف إلى طرف أو packet loss أو توافق MediaCodec على هاتف المستخدم. هذه اختبارات أجهزة فعلية وتتطلب تشغيل الهاتف والكمبيوتر على الشبكة نفسها وقياس البث.

## قائمة اختبار الجهاز الفعلي
- [ ] `mirage doctor` يعثر على ADB وscrcpy ويعرض الإصدارين.
- [ ] USB: الهاتف يظهر بحالة `device` بعد الموافقة على رسالة تصحيح USB؛ هذا اختبار مستقل عن Wi-Fi.
- [ ] Wi-Fi: شغّل نقطة اتصال الهاتف وصِل Windows بها دون توصيل USB.
- [ ] Wi-Fi: فعّل Wireless debugging على Android 11 أو أحدث.
- [ ] Wi-Fi لأول مرة: افتح «الإقران باستخدام رمز»، وأدخل الرمز المؤقت عند طلبه في MIRAGE LINK.
- [ ] Wi-Fi: يكتشف ADB خدمات mDNS ومنافذ الاقتران والاتصال الفعلية، ثم يبدأ scrcpy دون إدخال IP:PORT يدوياً.
- [ ] Wi-Fi لاحقاً: بعد حفظ الاقتران، أعد الاتصال بالشبكة نفسها وشغّل العرض دون رمز جديد ما دام Android يحتفظ بالاقتران.
- [ ] نقطة اتصال الهاتف: بث 10 دقائق مع تسجيل FPS والانقطاعات.
- [ ] نقطة اتصال الكمبيوتر: بث 10 دقائق مع تسجيل FPS والانقطاعات.
- [ ] اختبار H.264 وH.265 إذا كان الهاتف يدعم كليهما.
- [ ] تدوين دقة المصدر، متوسط FPS، أدنى FPS، ومعدل البت.
- [ ] قياس التأخير بكاميرا عالية السرعة أو أداة قياس مناسبة، وعدم تقديره بصرياً فقط.

## حكم الاكتمال
نجاح الاختبارات الآلية والبناء يثبت سلامة الأجزاء البرمجية التي تغطيها الاختبارات فقط. لا توصف Wi-Fi بأنها مختبرة ميدانياً أو متوافقة مع كل الهواتف ونقاط الاتصال قبل إكمال قائمة اختبار الجهاز الفعلي أعلاه. قد تمنع بعض نقاط الاتصال عزل العملاء أو حجب mDNS الاتصال المحلي. لا توجد نتيجة أداء مضمونة مسبقاً.
