# MIRAGE LINK

تطبيق لعرض شاشة Android على Windows عبر USB أو عبر شبكة Wi-Fi محلية. وضع Wi-Fi الجديد يستخدم تطبيق Android مساعداً يلتقط الشاشة بموافقة المستخدم عبر MediaProjection، ويرسل H.264 إلى مستقبل Windows. لا يعتمد هذا الوضع على تصحيح ADB اللاسلكي ولا يحتاج إلى كابل USB أو إنترنت بعد تثبيت التطبيقين.

## طريقة Wi-Fi المطلوبة

1. ثبّت تطبيق **MIRAGE LINK Android Companion** على الهاتف.
2. شغّل نقطة اتصال الهاتف.
3. صِل الكمبيوتر بشبكة نقطة الاتصال من إعدادات Windows.
4. افتح تطبيق MIRAGE LINK في الهاتف واضغط **السماح بعرض الشاشة**، ثم وافق على نافذة Android الرسمية.
5. على الكمبيوتر افتح MIRAGE LINK واضغط **اختيار شبكة Wi-Fi** إذا لم يكن متصلاً بنقطة الاتصال.
6. اضغط **عرض عبر Wi-Fi**. سيستمع الكمبيوتر لإشارة الهاتف على الشبكة، يكتشف عنوانه تلقائياً، ثم يفتح نافذة عرض الفيديو.
7. اترك تطبيق الهاتف وخدمة المشاركة يعملان أثناء العرض. لإيقاف البث اضغط **إيقاف العرض** في Windows.

لا يلزم تشغيل خيارات المطور أو تصحيح أخطاء USB اللاسلكي. لا يلزم إدخال IP أو منفذ يدوياً. يجب أن يكون الهاتف والكمبيوتر على الشبكة المحلية نفسها، وأن تسمح الشبكة باتصال الأجهزة بعضها ببعض. عند ظهور مطالبة جدار حماية Windows اختر السماح على الشبكات الخاصة.

## تنزيل تطبيق الهاتف

افتح سير عمل **Android companion build** في تبويب Actions بمستودع GitHub، واختر أحدث تشغيل ناجح، ثم نزّل Artifact باسم `MIRAGE-LINK-Android-Companion-debug`. فك ضغط الملف وثبّت `app-debug.apk` على هاتف Android. قد يطلب Android السماح بالتثبيت من هذا المصدر. موافقة مشاركة الشاشة مطلوبة من النظام عند بدء جلسة الالتقاط.

## تنزيل برنامج Windows

افتح سير عمل **Windows portable GUI build** في تبويب Actions، ثم نزّل Artifact باسم `MIRAGE-LINK-Windows-Full` من أحدث تشغيل ناجح. فك الضغط وشغّل `تشغيل-MIRAGE-LINK.bat`. الحزمة تتضمن واجهة Windows وملفات فك ترميز H.264، كما تتضمن scrcpy وADB لوضع USB.

## اتصال USB

- فعّل تصحيح USB على Android ووصل الهاتف بكابل بيانات.
- وافق على نافذة الثقة التي تظهر على الهاتف.
- حدّد الجهاز في قسم USB واضغط بدء عرض الشاشة.
- وضع USB يستخدم scrcpy كمسار مستقل عن بث MediaProjection عبر Wi-Fi.

## متطلبات وملاحظات

- Windows 10/11.
- Android 8 أو أحدث للتطبيق المساعد (تم إعداد البناء على Android SDK 35).
- اتصال Wi-Fi محلي بين الجهازين؛ لا يلزم إنترنت أثناء العرض بعد تثبيت التطبيقين.
- جودة الفيديو تعتمد على الهاتف والشبكة؛ لا يوجد ضمان ثابت لمعدل 60 إطاراً/ثانية.
- التقاط الشاشة يحتاج موافقة Android الرسمية ولا يمكن تجاوزها.
- قد تمنع بعض نقاط الاتصال أو إعدادات عزل العملاء مرور بث UDP/TCP بين الأجهزة.
- iPhone/iPad غير مدعومين في هذه المرحلة.
- تحسين الصورة بالذكاء الاصطناعي أو رفع الدقة غير مضافين.
- نجاح بناء CI لا يعادل اختباراً ميدانياً على كل هاتف وشبكة؛ يلزم اختبار عملي على الجهاز المستهدف.

## بناء واختبار المشروع من المصدر

متطلبات البناء: Python 3.10+ وJava 17 وGradle لبناء تطبيق Android.

```powershell
py -m pip install -e ".[dev]"
py -m pytest
```

لبناء نسخة Windows محمولة:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\packaging\build-windows.ps1"
```

لبناء APK:

```powershell
cd android-companion
gradle assembleDebug
```

## بنية نقل Wi-Fi

- Android: MediaProjection → MediaCodec H.264 → TCP المنفذ 27183.
- اكتشاف الهاتف: UDP المنفذ 27184 مع إعلان عنوان TCP على واجهات IPv4 النشطة.
- Windows: مستمع UDP يلتقط الإعلان، يتصل عبر TCP، ويفك H.264 باستخدام PyAV.
- USB: ADB + scrcpy، دون تغيير مسار USB.
