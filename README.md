# MIRAGE LINK — إصدار Windows التجريبي

محرك الاتصال والبث الأولي لأجهزة Android إلى Windows/Linux/macOS بالاعتماد على ADB وscrcpy كمحرك بث مُجرّب ومفتوح المصدر. هذه المرحلة توفر طبقة تشغيل واكتشاف واتصال واختبارات آلية؛ ولا تدّعي أنها بديل مستقل عن scrcpy أو أنها اختُبرت على أجهزة فعلية لم تُوصل أثناء التطوير.

## المتطلبات
- Python 3.10 أو أحدث.
- Android Platform Tools (يتضمن `adb`).
- scrcpy مثبت محلياً (الإصدار 2.4 أو أحدث موصى به).
- Android مع تفعيل خيارات المطور وتصحيح USB أو تصحيح USB اللاسلكي.

## تشغيل سريع على Windows
1. ثبّت Python وADB وscrcpy، أو ضع مسارات `adb.exe` و`scrcpy.exe` في PATH.
2. افتح PowerShell داخل مجلد المشروع.
3. شغّل:

```powershell
py -m pip install -e ".[dev]"
mirage doctor
mirage devices
mirage stream
```

أو دون تثبيت الحزمة:

```powershell
py -m mirage_link doctor
py -m mirage_link devices
py -m mirage_link stream
```

## اتصال USB
- صِل الهاتف بكابل بيانات سليم.
- فعّل تصحيح USB، وافق على بصمة RSA في الهاتف.
- تحقق أن `mirage devices` يعرض الحالة `device` وليس `unauthorized`.
- نفّذ `mirage stream`.

## اتصال Wi-Fi دون إنترنت
يشترط وجود الهاتف والكمبيوتر على الشبكة المحلية نفسها. يمكن أن تكون الشبكة نقطة اتصال الهاتف أو نقطة اتصال الكمبيوتر؛ لا يلزم اتصال بالإنترنت.

**Android 11 فأحدث (الاقتران اللاسلكي):**
1. افتح خيارات المطور > تصحيح أخطاء USB اللاسلكي.
2. اختر «الإقران باستخدام رمز الاقتران».
3. نفّذ `mirage pair عنوان-IP:منفذ-الاقتران رمز-الاقتران`.
4. ارجع إلى شاشة تصحيح أخطاء USB اللاسلكي وخذ عنوان الاتصال والمنفذ (قد يختلفان عن منفذ الاقتران).
5. نفّذ `mirage connect عنوان-IP:منفذ-الاتصال`.
6. نفّذ `mirage devices` ثم `mirage stream`.

**Android 10 وأقدم أو وضع TCP/IP التقليدي:**
- بعد توصيل USB أول مرة، نفّذ `mirage tcpip 5555`.
- اعرف عنوان الهاتف من إعدادات الشبكة، ثم `mirage connect IP:5555`.
- هذه الطريقة تعتمد على إصدار Android وسياسة الشركة المصنّعة.

لا تفترض أن عنوان الهاتف دائماً `192.168.43.1`؛ استخدم العنوان المعروض في الهاتف.

## أوامر CLI
| الأمر | الوظيفة |
|---|---|
| `mirage doctor` | فحص الأدوات والاتصال |
| `mirage devices` | عرض الأجهزة وحالتها |
| `mirage pair IP:PORT CODE` | اقتران Android اللاسلكي |
| `mirage connect IP:PORT` | الاتصال بجهاز على الشبكة |
| `mirage tcpip [PORT]` | تفعيل ADB TCP/IP عبر USB |
| `mirage stream` | بدء البث للجهاز المحدد أو الأول |
| `mirage stream --serial SERIAL` | اختيار جهاز بعينه |
| `mirage stream --codec h264` | تحديد الترميز (h264/h265/auto) |
| `mirage stream --max-fps 60 --bit-rate 40M` | تحديد سقف الإطارات ومعدل البت |
| `mirage stream --max-size 1920` | اختياري: فرض حد للحجم؛ لا تستخدمه إذا أردت الدقة الأصلية |

## ملف الجودة الحالي: طبيعي مرتفع
- يلتقط scrcpy شاشة الهاتف بدقتها الأصلية؛ لا يرسل MIRAGE LINK قيمة `--max-size` افتراضياً، ولذلك لا يطلب تصغير الصورة.
- معدل البت الافتراضي 40 ميغابت/ثانية، مع H.264 وتحديد أقصى 60 إطاراً/ثانية. هذا إعداد مرتفع لتقليل آثار الضغط، وليس زيادة للدقة أو ضماناً لتحسن مرئي كبير عند مصدر 720×1640. إذا ظهرت تقطعات أو ارتفع الحمل، اخفضه إلى 24M أو 16M. وقد لا يستفيد المصدر من كامل المعدل بسبب حدود مرمّز الهاتف.
- لا يضيف النظام فلاتر تشبع أو تباين أو تغيير Gamma؛ الهدف إبقاء الألوان طبيعية كما يرسلها الهاتف. قد تختلف الألوان بسبب شاشة الكمبيوتر وملف تعريف الألوان وإعدادات HDR/سطوع الشاشة.
- تطابق الألوان بنسبة 100% غير مضمون بمجرد رفع معدل البت؛ scrcpy ينقل فيديو مضغوطاً، ثم تعرضه شاشة الكمبيوتر وفق معايرتها وملف ICC وHDR ودرجة اللون. لا نضيف حالياً فلاتر تصحيح عشوائية لأنها قد تجعل ألواناً أخرى أسوأ. للحصول على أقرب تطابق: أوقف HDR وNight light في Windows مؤقتاً، أعد ملف تعريف الشاشة إلى الوضع الافتراضي أو sRGB إن كان متاحاً، واجعل وضع ألوان شاشة الكمبيوتر Standard/sRGB لا Vivid، ثم قارن صورة ثابتة على الهاتف والكمبيوتر بنفس السطوع تقريباً. إذا بقي الاختلاف كبيراً نحتاج صورة مقارنة ومعلومات الشاشة لتحديد هل السبب من الترميز أم من الشاشة.
- يمكن تكبير نافذة العرض أو ملء الشاشة، لكن هذا لا يحوّل مصدر 720×1640 إلى تفاصيل 2K/4K/8K حقيقية. شاشة المستخدم التي تم اختبارها هنا أرسلت 720×1640، وهي أيضاً الدقة الأصلية التي أبلغ عنها Android.
- تكبير الصورة بالذكاء الاصطناعي إلى دقة أعلى يتطلب مرحلة معالجة منفصلة على الكمبيوتر، ومعالجة GPU وذاكرة إضافية وقد يزيد التأخير. لم تتم إضافتها أو الادعاء بوجودها في هذا الإصدار.
- لا يوجد ضمان مطلق لـ60 FPS أو زمن تأخير معين؛ يجب قياس الأداء على الجهاز الفعلي.

## الاختبارات

## حدود المرحلة الأولى
- محرك الفيديو والصوت الفعلي هو scrcpy؛ المشروع ينسّق ADB والاتصال وخيارات البث.
- توجد واجهة Windows عربية تجريبية في المستودع، لكنها ما زالت بحاجة إلى اختبار ميداني وتحسينات قبل اعتبارها إصداراً مستقراً. لا يوجد تطبيق Android مرافق مستقل أو تحكم مخصص للألعاب بعد.
- iPhone/iPad خارج هذه المرحلة بسبب اختلاف بروتوكولات وقيود iOS.
- لا يوجد ضمان مطلق لـ60 FPS أو زمن تأخير معين؛ يجب قياسه ميدانياً.

## الترخيص
كود MIRAGE LINK في هذا المستودع مرخّص وفق MIT. scrcpy وAndroid Platform Tools أدوات خارجية مستقلة، ولكل منها ترخيصها وشروط توزيعها. لا تُضمّن ملفاتها التنفيذية في حزم المشروع دون مراجعة تراخيصها.


## واجهة Windows الحالية — تجريبية وقيد التحقق

شغّل الواجهة العربية بالأمر:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\\scripts\\تشغيل-MIRAGE-LINK.ps1" -Action gui
```

تتضمن الواجهة اكتشاف الأجهزة والاقتران والاتصال اللاسلكي، مع ملفات جودة، وتعرض حالة عملية البث. عند تفعيل قياس الإطارات تحفظ مخرجات scrcpy في سجل محلي داخل مجلد بيانات المستخدم: `%LOCALAPPDATA%\\MIRAGE LINK\\logs\\scrcpy-performance.log`. مع ملفات جودة:
- **فائق الوضوح:** H.264 و40M وحتى 60 إطاراً/ثانية؛ يحافظ على دقة المصدر ولا يحوّلها إلى دقة أعلى.
- **سلاسة أعلى:** H.264 و24M وحتى 60 إطاراً/ثانية؛ خيار لتخفيف معدل البيانات عند وجود اختناق.
- **تجربة HEVC:** H.265 و20M وحتى 60 إطاراً/ثانية؛ تجريبي ويتطلب دعم الهاتف وscrcpy، وقد يفشل على بعض الأجهزة.

يمكن تعديل الترميز ومعدل البت ومعدل الإطارات يدوياً. قيمة 60 هي سقف مطلوب وليست ضماناً لمعدل إطارات فعلي ثابت. لم يُضف حتى الآن تكبير بالذكاء الاصطناعي أو ادعاء بإنشاء تفاصيل 2K/4K؛ ستتم دراسة هذه المعالجة منفصلة وقياس أثرها على التأخير قبل اعتمادها.


### ضبط السلاسة وقياس الأداء

تضيف الواجهة خيارين للاختبار:
- **تعويض اهتزاز البث:** 0ms هو الاختيار الافتراضي لأقل تأخير. جرّب 25ms أو 50ms فقط إذا ظهر تقطع متذبذب؛ زيادة المخزن تضيف تأخيراً مقصوداً.
- **قياس الإطارات الفعلي:** يفعّل `--print-fps` في scrcpy. حد 60 إطاراً/ثانية سقف وليس ضماناً؛ معدل الإطارات يتغير بحسب نشاط الشاشة وقدرات الهاتف.

يُفضّل H.264 عند أولوية التأخير المنخفض. لا يوجد تكبير حقيقي أو استعادة تفاصيل حتى الآن؛ لا تُعامل نافذة أكبر على أنها دقة مصدر أعلى.


## بناء نسخة Windows المحمولة

يتوفر سكربت تجهيز نسخة Windows ذات مجلد محمول وواجهة رسومية:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\packaging\build-windows.ps1"
```

ينشئ الناتج في `dist\MIRAGE-LINK`. يحتاج البناء إلى اتصال إنترنت أول مرة لتنزيل PyInstaller إن لم يكن مثبتاً. إذا كان مجلد scrcpy موجوداً في المسار الافتراضي على سطح المكتب، ينسخ السكربت حزمة scrcpy/ADB كاملة إلى مجلد الأدوات مع ملفاتها الأصلية؛ وإلا ينشئ التطبيق ويطلب تثبيت الأدوات خارجياً. شغّل `تشغيل-MIRAGE-LINK.bat`.

**حدود النسخة الحالية:** هذه نسخة Windows فعلية لواجهة وتحكم اتصال ADB وتشغيل scrcpy، وليست محرك فيديو مستقلاً. لا تتضمن تطبيق Android مرافقاً أو مستقبل iOS أو تكبيراً بالذكاء الاصطناعي. يلزم اختبار الحزمة على جهاز Windows فعلي قبل وصفها بأنها إصدار نهائي مستقر. لا تُحذف ملفات تراخيص الأدوات الخارجية عند إعادة توزيعها.


## حالة البناء والتحقق

- يتم اختبار المحرك والواجهة على Windows وUbuntu عبر GitHub Actions.
- سير عمل Windows ينشئ مجلد واجهة محمولة ويرفعه كملف Actions Artifact باسم `MIRAGE-LINK-Windows-GUI`. هذا الأثر لا يضم scrcpy أو ADB؛ يجب توفيرهما من تثبيت مستقل. النسخة التي تُبنى على جهاز المطور قد تضم مجلد scrcpy المحلي إذا كان المسار المحدد يحتوي على `scrcpy.exe`.
- سجل قياس الإطارات في الواجهة الرسومية محفوظ في `%LOCALAPPDATA%\\MIRAGE LINK\\logs\\scrcpy-performance.log` حتى يمكن فحصه بعد إغلاق نافذة البث.
- نجاح الاختبارات الآلية أو إنشاء ملف EXE لا يعني اكتمال اختبار الهاتف الحقيقي. حالة الإصدار تبقى تجريبية إلى أن ينجح اختبار USB وWi-Fi، وتُراجع سجلات FPS، ويُختبر تشغيل الحزمة على Windows نظيف.
- لا توجد حالياً نسخة Android مستقلة أو دعم iOS أو تحسين صورة بالذكاء الاصطناعي. هذه ليست ميزات مخفية أو مكتملة.


### تنزيل نسخة Windows من GitHub Actions

بعد اكتمال سير عمل **Windows portable GUI build** بنجاح:
1. افتح تبويب Actions في مستودع GitHub.
2. اختر أحدث تشغيل ناجح لسير العمل **Windows portable GUI build**.
3. من قسم Artifacts نزّل `MIRAGE-LINK-Windows-GUI` وفك ضغطه.
4. هذه الحزمة تحتوي برنامج الواجهة فقط؛ يجب تثبيت ADB وscrcpy منفصلين أو إنشاء الحزمة محلياً مع مجلد scrcpy الموجود على جهازك.

لا تستخدم ملف Actions Artifact على أنه حزمة مستقلة تماماً عن ADB/scrcpy.
